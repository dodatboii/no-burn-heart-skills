# 模型显存建模与资源估算

先识别实际结构和运行路径，再建立每卡显存账本；有小模型实测时，优先用“以小验大”校准难以计算的部分。只分析用户要求的阶段；没有实测时交付理论预算和可执行的测量方案，不编造实测数值。

## 读取模型与运行信息

1. 从用户提供的本地配置、模型仓库、模型卡和实现中提取结构。分析新发布模型时查阅官方来源，记录模型 revision、框架版本、算子路径及来源链接；无法取得的版本标为未知。读取权重索引、张量元数据或 meta device 模型即可统计时，避免下载完整大模型。
2. 分开统计 routed experts 与公共参数，检查共享专家、latent 投影、首层 Dense、词表和绑权、输出头及多模态分支。层型不一致时逐类求和。总参数、激活参数和量化文件大小不能互相替代。
3. 确认任务是训练、推理还是 RL；读取每卡 micro-batch、实际 token 长度、并发、prefill token 预算、精度、优化器、offload、重计算分段、并行网格及硬件拓扑。缺少的信息先查现有配置，再集中询问影响结论的项目。可独立完成的结构分析继续推进。

## 选择分析路线

- **理论估算**：读取 [memory-models.md](references/memory-models.md)。分别计算状态/权重、临时恢复参数、激活、缓存和运行开销；按实现选择激活及缓存公式。系数未知时给出结构项或明确的情景范围，不能将未校准系数默认为 1 后称为精确峰值。
- **以小验大**：有小模型实测或用户希望设计验证实验时，读取 [small-to-large.md](references/small-to-large.md)，沿五步推导。只把实际已测的阶段用于校准；训练剩余量不能直接作为推理开销。
- **参考案例**：需要完整数值示范或分析 Kimi-K3 时，读取 [kimi-k3-example.md](references/kimi-k3-example.md)。它是原始实践记录的整理，经验数值及历史代码路径不自动适用于新环境。
- **数值核算**：使用 [estimate_memory.py](scripts/estimate_memory.py)，输入格式见 [calculator.md](references/calculator.md)。它负责单位换算和账本计算，不代替模型解析、算子分析或硬件验证。

## 计算时必须保持的口径

- 数值结果默认 GiB；参数数量用十进制。纯变量公式不夹入单位转换，代入数值时再转换。日志中的 `_gb`、设备工具中的 `MB` 必须核对代码或产品说明，不能仅按名称判断。
- 区分 allocated、reserved 与设备总占用。reserved 通常包含 allocated，不相加。扣除的已知项必须属于同一测量口径，且在测量峰值时驻留；不能从某个阶段峰值减去其他阶段各项的独立最大值。
- 全模型状态按实际有效分片计算；训练状态 16 B/param、临时参数 8 B/param 都是特定格式的示例。PP 按 stage、TP/CP 按真实本地张量核算，不统一除以所有并行度。
- Full Recompute 分开算边界 checkpoint 与活动分段，按唯一存储去重。Attention 与 MoE 的保存张量可能同时存活，不能默认只取两个模块占用的较大者。
- 单卡专家 token 数只有在相应数据布局下才简化为 BSK；专家总数 E、top-k K、EP 不可混作同一个放大系数。恢复层数需重算状态、checkpoint 和逐层驻留量，活动分段不能直接乘深度比。
- 理论账本与实测残差是两种核算路径。残差已包含的临时参数、工作区等不重复加回。80% 的整块状态预算与逐项扣除法也不能叠加使用。
- 核对实际进程组和部署拓扑；EP=DP×TP、F=EP×eFSDP 均只适用于对应布局。每卡专家数由 E/EP 决定，不能由 FSDP/EP 推断。
- 完成权重和缓存静态预算后，还需评估 prefill、decode、初始化及权重同步等相关阶段。显存有余量只支持候选配置，不代表已验证能跑通或吞吐合适。

## 交付

用简洁中文交付所需阶段的分析，依次包含模型结构与来源、理论计算、实测外推（有数据时）、候选并行配置及余量。公式先列变量表达式，再代入已知值；未知项明确保留或列出待补值。区分实测、理论与经验外推，精度与输入可信度一致。

每个候选给出设备/节点数量、关键并行度、单卡预算及限制它的原因。说明最关键的待验证项，并给出最小测量建议，例如补一次优化器状态已初始化的完整训练步，或目标并发下的 prefill/decode 峰值。只在用户要求时修改现有文档、运行模型或发布结果。
